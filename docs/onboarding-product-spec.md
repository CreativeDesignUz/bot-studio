# Bot Studio: единый onboarding

## Цель

После выбора шаблона клиент не попадает в пустой дашборд с нулевыми метриками. Он видит готовую структуру своего типа бизнеса, понимает возможности бота и добавляет первый полезный элемент.

## Типы шаблонов

| Тип | Первый элемент | Готовые разделы |
| --- | --- | --- |
| Доставка еды | Блюдо | Меню, категории, корзина, адрес, зона доставки, заказ, оплата |
| Интернет-магазин | Товар | Каталог, категории, остатки, корзина, заказ, доставка, оплата |
| Услуги и запись | Услуга | Услуги, специалисты, расписание, запись, напоминания, оплата |
| Курс и обучение | Урок | Программа, модули, уроки, ученики, доступ, прогресс, оплата |

## Сценарий первого запуска

1. Клиент выбирает тип бота и задаёт название проекта.
2. Система создаёт структуру шаблона без демонстрационных заказов и выручки.
3. Empty state показывает три основные возможности выбранного шаблона.
4. Чек-лист отмечает автоматически созданные настройки и откладывает подключение канала.
5. Главная кнопка предлагает добавить первый товар, блюдо, услугу или урок.
6. После сохранения появляется карточка первого элемента и два действия: добавить ещё или перейти в кабинет.
7. Метрики появляются только после реальных событий. До этого вместо них показывается прогресс настройки.

## Единая модель состояния

```ts
type BotTemplate = "delivery" | "store" | "service" | "course";
type OnboardingStage = "template_selected" | "structure_ready" | "first_item" | "ready";

type BotWorkspace = {
  id: string;
  template: BotTemplate;
  onboardingStage: OnboardingStage;
  selectedBot: boolean;
  profile: { name: string; description?: string; logoKey?: string };
  theme: { primary: string; secondary: string; splashLogoKey?: string };
};
```

Первый элемент хранится через общий контракт `CatalogItem`, а тип определяет поля и подписи интерфейса. Это позволяет вебу, Telegram Mini App и iOS использовать один API и один прогресс onboarding.

## Адаптация по платформам

### Веб-кабинет

- Слева остаются прогресс и четыре шага.
- В центре — explanation, empty state и форма первого элемента.
- После первого элемента открывается обычная навигация кабинета.

### Telegram Mini App

- Верхняя панель всегда показывает выбранного бота.
- Шаги сворачиваются в процент готовности.
- Основное действие закреплено снизу с учётом safe area.
- Выбор другого бота открывается нижним листом поверх `document.body`.

### iOS-приложение

- `NavigationStack` для шагов onboarding.
- `safeAreaInset(edge: .bottom)` для главного действия.
- `sheet` с detents для переключения ботов.
- Системный `PhotosPicker` для логотипа и изображения элемента.
- Состояние загружается из того же backend API; локально кэшируются выбранный бот и незавершённая форма.

## Правила UX

- На экране всегда один выбранный бот; режима «Все боты» нет.
- Не показывать нулевые метрики до первого реального события.
- На каждом шаге только одно главное действие.
- Подключение Telegram и оплаты не блокирует добавление первого элемента.
- Пользователь может выйти и продолжить с последнего завершённого шага.
