# Bot Studio — выпуск без регрессий

Дата фиксации: 2026-10-12. **Состояние: релиз заблокирован, пока не выполнен чек-лист.**

## Правило публикации

- PR / push запускают только проверки качества. Изменения не публикуются автоматически на общий Staging.
- Staging deploy — **только вручную** через GitHub Actions `workflow_dispatch` на `main` после ревью и зелёных тестов. Production не затрагивать.
- Тестовый выпуск делается из проверенного commit SHA. Для тестирования непроверенной ветки следует использовать отдельное изолированное preview-окружение, а не перезаписывать общий staging.
- Не утверждать «работает», если есть только зелёная сборка. Разделять `CODE`, `CI`, `DEPLOY`, `LIVE E2E`.
- Не запускать реальные публикации и не переносить миграции Production без согласования и проверенного отката.

## Критичные дефекты (P0)

1. На реальном экране каталога и оформления Mini App у существующего бота всплывает **«Укажите бота»**. Установить, какие конкретно ответы возвращают `/api/catalog`, `/api/catalog/categories` и `/api/miniapp/design`. Проверять валидный UUID, непросроченную сессию и передачу текущего `botId` во всех запросах.
2. Некоторые основные и активные кнопки выглядят как сплошные тёмные плашки **без видимого текста**. Проверить computed styles, каскад CSS, contrast ratio, Tailwind и браузерные скриншоты. Не исправлять отдельными hex-переопределениями, пока не установлена первопричина.
3. Telegram runtime для покупателя открывает `/workspace` (кабинет продавца) вместо покупательского Mini App, которого нет в этой ветке. Не объявлять /start и оплату работающими до E2E.
4. Авторизация Google/Telegram и стабильность cookies не прошли настоящий browser E2E. Проверить авторизованный GET `/api/workspace` и сохранение сессии после refresh.
5. Сверка `SUPABASE_URL` существующего staging Worker с ожидаемой базой Staging ещё не подтверждена runtime-диагностикой.

## Строгий чек-лист приёмки

| Сценарий | Доказательство |
| --- | --- |
| Google → вход → кабинет → refresh | Playwright trace + успешный авторизованный ответ |
| Telegram → вход → кабинет → refresh | Telegram OAuth/OIDC E2E + защищённый cookie |
| Выбор бота и переключение ботов | Выбранный UUID используется в каждом запросе; изоляция tenant |
| Категория: создать, сохранить, обновить | Данные остались после refresh; DB readback |
| Товар/блюдо: создать, изменить, удалить | DB readback и подтверждение в UI |
| Оформление Mini App | Чтение, сохранение, refresh, отсутствие ошибки «Укажите бота» |
| Заказы | Список; изменение статуса с проверкой owner и сохранением |
| Telegram Mini App | /start → каталог → корзина → тестовый заказ → кабинет продавца |
| Визуальные тесты | Скриншоты desktop/mobile; кнопки Primary/Secondary/Active, контраст, состояние disabled |
| Безопасность | Разграничение ботов, неверный UUID, 401/403, запрет доступа к чужим данным |

Не использовать живую Production базу для тестовых заказов. Для сценариев логина нужны тестовые пользователи или разрешённые тестовые сессии; без них маркировать NOT TESTED, не PASS.
